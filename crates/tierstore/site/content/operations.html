Operations

Starting and stopping tierstore, what it answers to a probe, what it prints, and what it does not export.

On this page: starting stopping probes the start-up self-test exit statuses metrics upgrading

Starting

The example unit does not start at install or at boot, and it is skipped while /etc/tierstore/access.key does not exist. Start it by hand when the key files are in place: systemctl start tierstore. A start that fails is tried again after 30 seconds, up to 5 starts in an hour, then systemd gives up until systemctl reset-failed tierstore. Exit status 2 (a command line the parser refused, or two keys with one access key id) and exit status 3 (a tier that answered the self-test wrongly) are not retried: RestartPreventExitStatus=2 3.

The process prints tierstore <version> listen=<address> on stdout once it is bound, and its other messages on stderr. It reads no environment variable. No message of the process carries a secret.

Stopping

systemd sends SIGTERM. The process answers /readyz 503, serves for --drain-lb-wait so that a load balancer sees it, refuses new requests, waits for those in flight for at most --drain-deadline, gives up the reconciler's lease and exits 0. TimeoutStopSec= in the example unit is set above the sum of the two flags and the lease's wait, so that systemd does not send SIGKILL to a drain in progress: if you raise --drain-deadline, raise it too.

Probes

None of these is signed, so a bucket cannot be called healthz, readyz or usagez.

Why /usagez is separate: puts ignore a usage older than 30 seconds, as if the hot tier were not full, so a stopped reconciler would otherwise show nowhere. A load balancer probes /readyz, because one stopped reconciler would otherwise take every node out. Puts are not refused when the usage is stale.

The start-up self-test

Before it binds its address the process asks each tier the questions its guarantees rest on: a create-only put of a key that exists must be refused, a replace on a wrong ETag must be refused and one on the right ETag must work, a ranged read must give exactly the range, a HEAD must give the size and the ETag of what was written, a listing after a key must page right, and on the cold tier the completion of a multipart upload over a key that exists must be refused. (Only the create-only completion is probed, not the refusal of a bad part list.) It uses keys under _tiering/selftest/, which clients never see; they are deleted afterwards, and keys a killed start left more than an hour ago (by the store's clock) are swept. Only keys under that prefix are ever deleted.

  • A tier answers one wrongly: exit 3, with the tier, the check and the answer on stderr, and no restart. Fix or replace the store. That includes answers that are a configuration error, such as 403 AccessDenied or NoSuchBucket.
  • A tier cannot be reached (down, a timeout, 408, 429, any 5xx but 501 and 507): it is asked again after pauses from one second doubling to thirty, for --backend-check-wait (five minutes by default, for each tier; 0s asks once). Then the start exits 1 with tier unreachable: <tier>: <error> and the unit tries again.
  • A tier is full (a full hot tier is a designed state): it starts, and the checks that need a write are skipped, with a line on stderr that says so. For a full cold tier the line is a warning that writes to the cold tier will fail.

--skip-backend-check multipart-conditional=<reason> leaves out the multipart check, for a store that lacks a conditional completion; the reason is written to stderr at every start. No other check can be skipped (exit 2). Without that check a multipart upload to the cold tier may replace an object that exists.

Metrics

There is no metrics endpoint. What there is to watch from outside: the three probes above, the process's stderr, and the objects tierstore keeps in the hot tier (_tiering/usage for the hot tier's usage, _tiering/proxies/ and _journal/ for each proxy's checkpoint and journal). The reconciler's hot-tier size and copy lag are values in the library (Reconciler::hot_bytes and Reconciler::copy_lag, "for metrics" in its documentation); the binary does not export them.

Upgrading

Nothing updates tierstore. Place the next binary as on the install page and restart the unit; the drain above makes the stop orderly. A release of kbf is a release of tierstore, so the version is kbf's.
