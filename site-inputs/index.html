Early development open source, Apache 2.0

Remote builds on your own machines.

kbf is a remote execution build farm for Buck2 and Bazel. Your build tool sends actions to one address; kbf runs them on your workers and keeps every result in a shared, content-addressed cache.

Install published with the first release

$ curl -fsSL https://kbf.dev/install.sh | sudo sh

The script verifies what it downloads and starts nothing. Other channels are on the install page.

Get started

From a host to a remote build in three steps

  1. 1

    Install the installer

    kbf-installer installs and verifies kbf, then takes update orders. Installing starts nothing. specified

    $ curl -fsSL https://kbf.dev/install.sh | sudo sh
  2. 2

    Set up a mode

    One host can run everything; a farm splits the roles. specified

    $ sudo kbf-installer setup --mode=all-in-one
  3. 3

    Point Buck2 at it

    In your .buckconfig, send actions and cache reads to the frontend. works today

    [buck2_re_client]
  engine_address = grpc://FRONTEND:8980
  action_cache_address = grpc://FRONTEND:8980
  cas_address = grpc://FRONTEND:8980

The quick start has every flag and what is built today.

Why we built it

    
A farm for the work that needs real machines

    
We wanted one open farm that runs the whole build, including the tests that need a real Mac, a real display or a real device, and that keeps what happened.

    
    
      
  • 
        
    UI, Mac and iOS tests on real machines
    
        
    These tests need a logged-in macOS session, Xcode and, for iOS, a device on a cable. kbf runs actions on Mac nodes as plain processes with their process tree, memory and network watched.
    
        
    Mac daemon: works todayiOS devices: specified
    
      
    • 
      
  • 
        
    Utilization you do not tune by hand
    
        
    In our experience, fitting actions to machines is hard to configure. kbf has no per-action reservations: it admits actions by CPUs and a memory ladder, and sizes cgroups from what it measures.
    
        
    works today

  • 
        
    Open source, all of it
    
        
    Some other farms are not completely open source. kbf is licensed under the Apache License 2.0.
    
        
    works today

  • 
        
    Every build kept, and a way to read it
    
        
    kbf records the attempts and cache hits of each invocation. We are designing a UI to explore all logs and metrics, and an API that an AI agent can use to fetch results.

Architecture and the rest

    
Four parts, one binary

    
    
      
  • frontend
    The one address clients, daemons and storage nodes know. Serves REAPI and schedules actions. Its state lives in a Postgres database you provide.
    • 
      
  • storage
    The content-addressable store and action cache: an SSD hot tier, flushed in the background to an object store.
    • 
      
  • daemon
    The worker. It fetches inputs, runs each action in isolation and uploads outputs. Linux and macOS.
    • 
      
  • all-in-one
    The parts in one process, for a single machine or a first try.
    • 
    

    
A host takes a role with --mode: frontend, storage, daemon, storage-and-daemon or all-in-one. Read the architecture, every setting and how a farm updates itself.

    
Status. Early development. The project is design-first: interfaces and tests land before features, and nothing here is ready for production use yet. Expect breaking changes. Each step on these pages says whether it works today or is specified.
